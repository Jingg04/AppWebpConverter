# Lazy Loading Done Right: loading='lazy', IntersectionObserver, and LCP Optimization

> **Summary:** Lazy loading done wrong is the #1 cause of failing Google LCP scores. Learn native browser loading='lazy', intersection thresholds, and the above-the-fold rule.




## Frequently Asked Questions

### Why is putting loading='lazy' on hero images disastrous?

The Largest Contentful Paint (LCP) element is almost always your hero image. Adding <code>loading='lazy'</code> forces the browser to delay requesting the image until layout calculations finish, delaying LCP by 1 to 2 full seconds and destroying your Core Web Vitals score.

### Which images SHOULD be lazy loaded?

Every image positioned below the initial viewport fold (e.g. blog post body illustrations, footer logos, product review galleries) should have <code>loading='lazy'</code> to save bandwidth.

### How far from the screen does native lazy loading trigger?

Browsers use dynamic thresholds based on network speed (e.g. Chrome triggers loading ~1,250px before entering the viewport on fast 4G, or ~2,500px on slow 3G) ensuring images finish rendering before the user scrolls them into view.
