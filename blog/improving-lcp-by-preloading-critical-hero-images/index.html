Improving Largest Contentful Paint (LCP) by Preloading Critical Hero Images

D
Dr. Sarah Chen Head of Web Performance Architecture
Published: 2026-11-09 8 min read ✓ Verified Technical Review
Table of Contents

Largest Contentful Paint (LCP) measures when the main content of a webpage has finished rendering on screen. In over 80% of websites, that largest visual element is a hero banner image. If your hero image is buried in an external CSS file (background-image: url(...)) or sits midway down the HTML document, the browser cannot discover it until late in the load cycle, triggering devastating LCP penalties.

The 2 Weapons for Sub-Second LCP

1. The HTML Head Preload Link

Inform the browser's preload scanner about the hero image immediately upon reading the first bytes of the HTML head:

<head>
  <link 
    rel="preload" 
    as="image" 
    href="hero-1200.webp" 
    imagesrcset="hero-640.webp 640w, hero-1200.webp 1200w" 
    imagesizes="100vw" 
    fetchpriority="high" />
</head>

2. The fetchpriority="high" Attribute

By default, images are downloaded with 'Low' network priority. Adding fetchpriority="high" tells the browser engine to prioritize the hero image over non-critical stylesheets and deferred scripts.

Frequently Asked Questions

What is the recommended threshold for Google's LCP metric?

Google Core Web Vitals classifies an LCP score under 2.5 seconds as 'Good', between 2.5s and 4.0s as 'Needs Improvement', and over 4.0s as 'Poor'. High-performing websites target under 1.2 to 1.5 seconds.

What is the 'Resource Load Delay' in LCP breakdown?

Resource load delay is the wasted time between when the page begins loading and when the browser discovers the image URL. Preloading in the HTML <head> reduces this discovery delay to zero.

Can you preload responsive images that use srcset?

Yes. Use <code>imagesrcset</code> and <code>imagesizes</code> inside your <code>&lt;link rel='preload'&gt;</code> tag. The browser will select and preload the identical responsive candidate that matches the viewport.
